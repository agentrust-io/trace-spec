# TR-ANC: Transparency

Checks that the record was entered in a public, append-only log, so it cannot be quietly replaced later. TR-ANC-001 checks the link to the log entry. TR-ANC-002 uses a receipt and the registry entry you supply to prove, offline, that this exact record is in that entry. Both apply from Level 2.

Technical detail: what the receipt proof covers

The log follows SCITT, the IETF format for transparency services. The receipt carries an inclusion proof (a short list of hashes linking the record to a Merkle root, the single hash that commits to the whole log). The receipt's `merkle_root` and `leaf_count` must equal those of the registry entry you pass with `--entry` (one line in the shape of Anchor Format §4), and the proof is then replayed against that root. Nothing yet identifies an entry from the `transparency` URI, so the check does not establish that the entry is the one the record names, and the pass message says so (trace-spec#448 finding 21). Whether a public log really published the entry is also outside this module, as [Known limitations](https://trace.agentrust-io.com/conformance/LIMITATIONS/index.md) explains.
