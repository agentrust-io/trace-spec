# Test Modules

The TRACE conformance suite is divided into eight modules. A module is a group of related checks on one part of a record, such as its signature or the hardware it says it ran on. Each module maps to a section of the TRACE specification, and each one's page lists every check with an example that passes and one that fails.

The table below uses the record's own field names (in code font). The [conformance levels](https://trace.agentrust-io.com/conformance/docs/levels/index.md) page says which modules run at which level.

| Module                                                                                  | ID Prefix | Spec Section | What It Tests                                                                                                                                                                              |
| --------------------------------------------------------------------------------------- | --------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Envelope](https://trace.agentrust-io.com/conformance/docs/modules/tr-env/index.md)     | TR-ENV    | §3.2         | `eat_profile` URI, `iat` validity, `subject` form, presence of `cnf.jwk.kty`                                                                                                               |
| [Signature](https://trace.agentrust-io.com/conformance/docs/modules/tr-sig/index.md)    | TR-SIG    | §3.2.1       | Private key leak detection, key type support, and the Ed25519 signature verification outcome                                                                                               |
| [Runtime](https://trace.agentrust-io.com/conformance/docs/modules/tr-rte/index.md)      | TR-RTE    | §3.1         | TEE platform enum, measurement format, RIM URI scheme, and verifier-issued nonce comparison                                                                                                |
| [Policy](https://trace.agentrust-io.com/conformance/docs/modules/tr-pol/index.md)       | TR-POL    | §3.1         | Policy bundle hash format, enforcement mode values, and whether the bundle at `policy_uri` has the declared digest                                                                         |
| [Appraisal](https://trace.agentrust-io.com/conformance/docs/modules/tr-apr/index.md)    | TR-APR    | §3.1         | Appraisal status enum, verifier URI form, `policy_ref` URI form, and timestamp plausibility. The appraisal policy is never resolved                                                        |
| [Transcript](https://trace.agentrust-io.com/conformance/docs/modules/tr-txn/index.md)   | TR-TXN    | §3.1         | Tool-call transcript hash binding                                                                                                                                                          |
| [Transparency](https://trace.agentrust-io.com/conformance/docs/modules/tr-anc/index.md) | TR-ANC    | §3.2         | SCITT receipt URI form (TR-ANC-001), and offline replay of the inclusion proof against the committed Merkle root when a receipt is supplied (TR-ANC-002). The URI itself is never resolved |
| [Provenance](https://trace.agentrust-io.com/conformance/docs/modules/tr-sca/index.md)   | TR-SCA    | §3.1         | SLSA provenance level and digest format                                                                                                                                                    |
